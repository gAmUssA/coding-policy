# 0014 — Host-gated local pi developer seats

Status: accepted

Date: 2026-10-24

## Context

Issue #71 needs optional local development without charging subscription
windows. The operator selected Flint for implementation only: local models
have not established sufficient independent reviewing or testing quality. An older host must use the same configuration safely. Pi changes its
process title and Herdr supplies no pi session ID. Neither a title nor the
newest transcript proves a dispatch. Pi 1.4.0 runtime captures establish its
intrinsic execution, loopback provider profile and JSONL v3 message format.

## Decision

Config 5 adds explicit host requirements and role restrictions. The example
profile requires Apple M5 or newer and 32 GiB RAM, an operator-selected
activation floor rather than a measured memory minimum. Snapshot 5
represents local capacity as `local_unmetered`, with no percentage. Local
workers rank before equally familiar metered candidates; metered algorithms
and judgment pins stay unchanged. Pi is developer only: the initial build and
fix rounds 1–3 each use a fresh launch with a full handoff brief. Later fixes,
risk escalation, large inputs and correction-plan rounds skip pi while keeping
metered developers eligible. Reviewers and the independent tester of record
remain metered. A pi developer is a contributor and cannot verify its work.
Config cannot enable other pi roles. The profile grants `read,bash,edit,write`
with extensions and MCP disabled, matching the captured pi 1.4.0 tools.

Commission pi through `start-local` in an idle shell pane. Preserve Herdr's
exact start argv with the observed PID, pane and terminal; recheck continuity
before input. Never adopt or resume an unrecorded process. Each fresh launch
gets a new session directory under the seat's teamlead state directory.
Bind the sole user turn to the exact dispatch prompt. A single linear native
session whose completed final assistant text is exactly the requested REPORT
marker and whose report exists proves delivery, independent of pane wrapping.
Other worker kinds retain their existing row guard. Native recovery is out
of scope. Source-bound delivery proves the worker declared completion, not that
its claims are true. The lead verifies the report before accepting results; metered independent review
and testing still gate delivery.

## Consequences

M1 hosts skip the optional seat without contacting pi. Failed host, local
provider or identity probes cannot create spendable local capacity. Configs
1–4 remain readable; old snapshots migrate as metered observations. Pi is
bounded to the captured 1.4.0 static loopback Ollama profile; other versions,
providers, branched sessions and auth overrides require new evidence. A new
commissioning entry point and durable receipt support the fresh-launch proof
without inventing retained argv or permission-bypass flags.

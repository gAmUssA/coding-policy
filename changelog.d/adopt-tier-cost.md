### Changed

- **Herdr tier policy picks the cheapest round each seat allows** (ADR `docs/adr/0007-herdr-tier-cost-policy.md`). Our live config carries full tier tables for every worker kind, so the old defaults decided real dispatches, and every round paid for them. Changes in `skills/herdr-teamlead/teamlead/tiers.py`, `references/model-tiers.md` and `references/team-operation.md`:
  - The tier qualification battery is retired (`teamlead/qualification.py` and its tests are removed; upstream jbaruch/coding-policy `963b95b`). It required a paired 5-case screen, a 20-case promotion battery and a weekly canary per model/effort/role before any tiered dispatch. No config held a recorded result, so it either blocked tiered dispatch or demanded a weekly campaign of paid trial runs. Judgment rounds stay pinned to the top model, every other round is independently reviewed and tested, and launch-argv proof still binds each dispatch to its configured row. A `qualification` field in an existing tier row is accepted and ignored (`RETIRED_TIER_FIELDS`), and `plan --preview-tiers` is accepted as a no-op, so current operator configs and scripts keep working. An unknown tier field is still refused.
  - A tester round escalates on evidence, not on its round name (upstream `a0491e5`). `hostile_verify` is the tester's default round, and the unconditional `round_type == "hostile_verify"` clause put every tester round on xhigh. Two risk flags, an oversized context or a recorded prior miss still escalate it. On that same evidence any Grok row now rises to `high`, Grok's ceiling: Grok's only model is already its top model, so before this a cheap Grok consultation or release row never escalated. The example's `hostile_verify` rows are now `high`.
  - Advisor and investigator default to a new non-judgment `consultation` round, release to `release_mechanics`, and `test_plan` leaves the judgment set (upstream `7f187b4`, adapted). The judgment round is one `--round ROLE=ROUND` away. Only a developer's `mechanical` round still requires the mechanical predicate; a release worker's loud failure is the release skill's own gates. A table without the new row keeps the role's earlier default when that row exists (`LEGACY_DEFAULT_ROUNDS`), so this is additive with no config schema bump.
  - The lead is no longer pinned to the top model (upstream `b595acc`, minimal adaptation). `lead` leaves `JUDGMENT_ROUNDS`; the lead's seat is a non-judgment `coordination` round selected like a worker's tier. A `lead` row in an existing table parses as the same seat under its old name. The judge seat keeps its model pin.
  - The Claude judgment pin accepts `claude-opus-5-5` beside the existing `opus-5` ids (upstream `8d5aa4a`). No Codex id was added without provider evidence.
  - For reviewer and tester seats the planner breaks a headroom tie in favour of a worker whose kind differs from every recorded contributor's, ahead of rotation count and name (drover `fleet-peers`). Each contributor's kind comes from its recorded ledger rows (`tier.kind`, `result.tier.kind` or the dispatch `provider`). Current config stands in only when nothing was recorded, so a reconfigured or removed contributor still counts. It is a preference only and never excludes a worker.
- **The Herdr state ledger moves to schema 7**. New tiered assignment rows no longer carry the battery's accepted qualification summary, so the owner bumps `STATE_SCHEMA_VERSION` in `skills/herdr-teamlead/teamlead/state.py`. The 6 → 7 migration drops `tier.qualification` and rewrites the file. A schema-7 row that still carries it is refused as unowned. A newer ledger takes the lagging-reader path: empty state in memory, file untouched. The read-only retrospective history reader accepts versions 1–7 without migrating and refuses newer ones. Recovery dispatch evidence keeps its original bytes. Reconciling a pre-upgrade pending dispatch promotes a copy of its saved tier without the retired field; before this fix it wrote the summary into a schema-7 row, and the next read rejected the ledger. An older owner build reads a migrated ledger as newer, so upgrade every dispatcher together.
- **The mechanical predicate (`MECHANICAL_TASKS`/`MECHANICAL_PROOFS`) is unchanged**. Upstream found its equivalent fired zero times in 702 assignments. Our local ledger holds 6 historical assignments, none on a mechanical round, which is too few to justify a change.
- Each behaviour change was shown failing with its code reverted: the qualification-free plan and ignored field in `tests/test_tier_integration.py`, the Opus 5.5 pin, the tester floor, the consultation, release, lead and legacy-fallback defaults in `tests/test_tiers.py`, the family tie-break in `tests/test_planner.py` and `tests/test_composition.py`, and the schema-7 migration, round trip and unowned-summary refusal in `tests/test_tier_integration.py`.
- Operator follow-up for an existing `~/.config/teamlead/config.json`: lower each `hostile_verify` row from `xhigh` to `high`. Add `consultation` and `coordination` rows (see `config.example.json`) to take the cheaper defaults. Delete the stale `qualification` arrays at the next edit.

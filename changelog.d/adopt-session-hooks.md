### Added

- **`hooks/session-start.sh`: one SessionStart hook that delivers every status.** Probed on tessl 0.115.0 with a throwaway fixture plugin under `$TMPDIR`: `tessl hook run` keeps only the LAST hook's output in a SessionStart group (also across groups), and the hook sees `TESSL_AGENT` and `TESSL_PLUGIN_DIR` but not `HERDR_ENV` or any other session variable. Our group ended with `beans-prime`, silent outside a beans repo, so Claude Code sessions received `{}`: no sync, version, or team status, and worker detection never saw `HERDR_ENV`. A scratch-project install of the old tree returned `{}` with `main` one commit behind; the new tree's native entry returned the merged statuses. The aggregator runs the hooks listed in `hooks/session-start-hooks.txt`, merges their `additionalContext`, and reports a failing or malformed child as its own status line. It is declared under `nativeHooks.claude-code` (single-string command, the session's environment intact) and stays the only portable SessionStart hook for other agents, where it exports `SESSION_START_MODE=portable`; the portable run defers when `TESSL_AGENT=claude-code`. The Codex adapter reads the same list for its allowlist, so the Codex plugin's separate handlers are unchanged. Idea from upstream jbaruch/coding-policy 73fbcb5 and 0.3.278.

### Fixed

- **`check-git-sync` never runs repo code, never fetches from a worker, and never hangs.** Every fetch and merge carries `-c core.hooksPath=/dev/null` (a ref update runs `reference-transaction`, a merge runs `post-merge`). The Herdr role is decided before the throttle stamp and the fetch: a worker reports drift as last fetched, and a session whose role cannot be proven (a failed probe with `HERDR_ENV` set, or a linked worktree in portable mode) neither fetches nor fast-forwards. The fetch is bounded by git's own `http.lowSpeedLimit`/`http.lowSpeedTime` and ssh `ConnectTimeout`/`ServerAlive*` on every platform, extending `GIT_SSH_COMMAND` or `core.sshCommand` rather than replacing it; `timeout`/`gtimeout` wraps it when present. Proven by reverting each piece: dropping `core.hooksPath` from the fetch or the merge fails the repo-hook case; dropping the low-speed limit leaves a fetch against a stalled HTTP server (with no `timeout` on `PATH`) running until the harness kills it. Ideas from upstream 7e436ae, 89393f0 and 0.3.278.
- **`check-policy-freshness` throttles per session directory.** One machine-wide stamp let a check in one project silence every other project for 24 hours. The stamp is now `last-check-<cksum of $PWD>`; the old `last-check` file is no longer read.
- **The `check-git-sync` harness no longer inherits the operator's `HERDR_ENV`**, which had made its results depend on the session that ran it.

### Changed

- **`check-git-sync` fast-forwards instead of only reporting** when the session is a proven non-worker in native mode, the default branch is checked out with no tracked changes, and a fresh fetch shows it strictly behind; `git merge --ff-only` refuses everything else. Off-default, dirty, diverged, portable, and unverified sessions are still reported, and `rules/sync-before-work.md` now says so. Idea from upstream 0.3.275. Upstream also fast-forwards a default branch that is not checked out (`fetch . origin/<b>:<b>`); not adopted, so the hook never moves a branch the session is not on.
- **`check-policy-freshness` is kept, not removed.** Upstream removed its counterpart as a duplicate of `check-tessl-latest`. Ours is not one: `check-tessl-latest` returns before `tessl update` in a project with no `gamussa/*` dependency and never reports other plugins, while `tessl outdated --json` reports every plugin in the project, third-party pins included (verified in a consumer pinning `jbaruch/blog-writer` 1.1.42 against 1.1.50). Removing it would leave those pins with no renewal signal (`rules/dependency-management.md` Freshness).

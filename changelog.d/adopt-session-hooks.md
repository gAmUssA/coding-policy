### Added

- **`hooks/session-start.sh`: one SessionStart hook that delivers every status.** Probed on tessl 0.115.0 with a throwaway fixture plugin under `$TMPDIR`: `tessl hook run` keeps only the LAST hook's output in a SessionStart group (also across groups), and the hook sees `TESSL_AGENT` and `TESSL_PLUGIN_DIR` but not `HERDR_ENV` or any other session variable. Our group ended with `beans-prime`, silent outside a beans repo, so Claude Code sessions received `{}`: no sync, version, or team status, and worker detection never saw `HERDR_ENV`. A scratch-project install of the old tree returned `{}` with `main` one commit behind; the new tree's native entry returned the merged statuses. The aggregator runs the hooks listed in `hooks/session-start-hooks.txt`, merges their `additionalContext`, and reports a failing or malformed child as its own status line. It is declared under `nativeHooks.claude-code` (single-string command, the session's environment intact) and stays the only portable SessionStart hook for other agents, where it exports `SESSION_START_MODE=portable`; the portable run defers when `TESSL_AGENT=claude-code`. The Codex adapter reads the same list for its allowlist, so the Codex plugin's separate handlers are unchanged. Without jq the children still run and the payload is one fixed status naming the jq install step; the aggregator never calls python3, so it needs no Direct Python Carve-Out entry. The decision, payload contract, shared list, portable-mode behavior, and compatibility are recorded in `docs/adr/0006-native-aggregating-session-start.md`. Idea from upstream jbaruch/coding-policy 73fbcb5 and 0.3.278.

### Fixed

- **`check-git-sync` never runs repo code, never fetches from a worker, and never loses local data.** Every git call that can update refs, the index, or the work tree carries `-c core.hooksPath=/dev/null`: the fetch (`reference-transaction`), the `git status` check (an index refresh runs `post-index-change`), and the fast-forward merge (`post-merge`). The Herdr role is decided before the throttle stamp and the fetch: a worker reports drift as last fetched, and a session whose role cannot be proven (a failed probe with `HERDR_ENV` set, or a linked worktree in portable mode) neither fetches nor fast-forwards. The merge passes `--no-overwrite-ignore`, so a path origin starts tracking that holds ignored local data refuses the fast-forward instead of overwriting it. Each guard has a case that fails with that guard reverted. Ideas from upstream 7e436ae, 89393f0 and 0.3.278; the status hook and the ignored-file overwrite were raised by Copilot on PR #52.
- **Session-start work has hard deadlines without `timeout`.** New `hooks/bounded-run.sh` runs a command in its own process group (bash job control, no python3) and returns its exit code once the whole group has exited, or stops the group (SIGTERM, a 2s grace, SIGKILL; liveness checked on the group, not the leader) and returns 124 at the deadline, even when the leader already exited 0. A runner stopped from outside stops and reaps its own group within a 1s grace, so nested runners never leave a process holding stdout.
  - `check-git-sync` always runs its fetch through it at `SYNC_FETCH_TIMEOUT`; git's `http.lowSpeedLimit`/`http.lowSpeedTime` and ssh `ConnectTimeout`/`ServerAlive*` (extending `GIT_SSH_COMMAND` or `core.sshCommand`, never replacing it) end most stalls sooner. An ssh that connects and then never answers is killed at the deadline.
  - `session-start.sh` runs each child through it (45s each, 120s total), reports a stopped or never-started child as its own line, keeps every other status, and exports the child's deadline as `SESSION_START_CHILD_DEADLINE_SEC`; `check-git-sync` caps its fetch at two thirds of it, so the inner deadline fires first.
  - `hooks/codex-session-start.py` exports the same variable, and on timeout sends SIGTERM, waits up to 3s for the whole group, sends SIGKILL, and drains output for at most 2s, instead of a SIGKILL that skipped the runner's trap followed by an unbounded drain.
  - Raised across Copilot's reviews on PR #52. The escalation, nested-runner, early-leader-exit, deadline-cap, stalled-child and adapter cases each fail with their fix reverted, on bash 3.2 and 5.3.
- **`check-policy-freshness` throttles per session directory.** One machine-wide stamp let a check in one project silence every other project for 24 hours. The stamp is now `last-check-<cksum of $PWD>`; the old `last-check` file is no longer read.
- **`check-tessl-latest` no longer updates plugins in portable mode.** Under `SESSION_START_MODE=portable` a Herdr worker cannot be ruled out, yet the hook still ran `tessl update --yes`, contradicting ADR 0006's report-only portable mode. It now reports installed versions, never "latest", and says why it did not update. An audit of the other children found no other write: `check-policy-freshness` runs `tessl outdated`, `herdr-team-status` reads the roster, `beans-prime` prints `beans prime`. A test through `session-start.sh` with a consumer `tessl.json` and a recording fake `tessl` failed first with `update --yes` logged in portable mode, and confirms native mode still updates. Raised by the Codex policy review on PR #52.
- **The hook harnesses prove outcomes, not durations.** Deadline cases assert the exit code, the process dead, and the absence of a marker a surviving process would write; the only elapsed-time check left is the `check-git-sync` stall watchdog, a named upper bound under the new testing-standards carve-out. The stall cases require the hook's exit 0, the stall server's teardown must end by signal (143/137), and the `check-git-sync` harness no longer inherits the operator's `HERDR_ENV`.

### Changed

- **`check-git-sync` fast-forwards instead of only reporting** when the session is a proven non-worker in native mode, the default branch is checked out with no tracked changes, and a fresh fetch shows it strictly behind; `git merge --ff-only` refuses everything else. Off-default, dirty, diverged, portable, and unverified sessions are still reported, and `rules/sync-before-work.md` now says so. Idea from upstream 0.3.275. Upstream also fast-forwards a default branch that is not checked out (`fetch . origin/<b>:<b>`); not adopted, so the hook never moves a branch the session is not on.
- **`check-policy-freshness` is kept, not removed.** Upstream removed its counterpart as a duplicate of `check-tessl-latest`. Ours is not one: `check-tessl-latest` returns before `tessl update` in a project with no `gamussa/*` dependency and never reports other plugins, while `tessl outdated --json` reports every plugin in the project, third-party pins included (verified in a consumer pinning `jbaruch/blog-writer` 1.1.42 against 1.1.50). Removing it would leave those pins with no renewal signal (`rules/dependency-management.md` Freshness).
- **`rules/testing-standards.md` Determinism: narrow exception for elapsed-time bounds in tests of code that enforces a deadline.** A fake clock cannot prove that real processes are stopped, so such a test may assert an upper bound on elapsed time only: a named constant at least 4x the deadline under test plus fixed slack, with no exact duration, lower bound, ordering, or date input, and a deterministic outcome preferred wherever one exists. Raised by the Codex policy review on PR #52.

### Fixed

- **A closed no-work initial developer assignment can be retried once through `teamlead recover-no-work`**. `skills/herdr-teamlead/references/team-operation.md` Stalled Workers calls a clean, unchanged stall a `not_sent`-equivalent that may be retried, but the owner refused a second initial assignment and the only way forward spent fix 1. The new owner command takes the saved `wait-report.sh --worktree --base` JSON. It verifies the stall against the dispatch's enrolled worker, report and task base, and requires the stalled checkout to resolve to the one worktree the developer brief's worktree field names. It then rechecks live state: the pane is gone, the enrollment is resolved, the report is absent, and the checkout is clean at the base. It then writes a receipt. `plan` and `apply` admit one fresh initial assignment of the unchanged brief, with a fresh, unoccupied report path and a fresh context. A dry run of the retry runs the static checks and contacts no Herdr. `apply` repeats every live check before any input and again immediately before reservation, so a report that lands late refuses the retry, and binds the retry to the receipt in the reservation save. The receipt keeps the checkout's canonical real path, and each retry gate first requires the brief's worktree to still resolve to it. A recovered refusal move no longer counts as the outstanding move, so the retry goes to a provider that has not refused that brief. The original row and the correction count are unchanged, and replay grants nothing more. Proven through `teamlead.sh` with a real git checkout and a real `wait-report.sh` run in `skills/herdr-teamlead/tests/test_no_work_recovery.py`. The test failed on the prior code with `invalid choice: 'recover-no-work'` and the initial slot refused. Adapted from upstream jbaruch/coding-policy 45f98ac2 (#763).

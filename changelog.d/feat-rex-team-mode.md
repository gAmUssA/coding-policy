### Added

- **Rex team mode: `skills/herdr-teamlead/rex-team.sh`** (ADR 0016). Run in a Rex terminal, it prints as JSON the environment Herdr gives a managed pane (`HERDR_ENV=1`, `HERDR_PANE_ID`, `HERDR_WORKSPACE_ID`, `HERDR_BIN`, `TEAMLEAD_HERDR_BIN`) plus `TEAMLEAD_BACKEND=rex`, mapped from `REX_BLOCK` and `REX_SESSION`. It execs nothing and has no side effects; the operator starts the lead with a jq `@sh` one-liner documented, with the script's contract, in `references/herdr.md` Running on Rex. That keeps the plugin's JSON-producing script contract with no rule exception; the user chose this over an exec launcher. Failures are a `{"error":{"code","message"}}` envelope on stderr with every string JSON-escaped (`not_in_rex`, `setup_error`, `usage_error` for any argument). The Rex adapter's `agent start` now starts each worker behind the same variables for its own block, so every `HERDR_ENV` mode check, hook and rule works in Rex unchanged. Rex sets `REX_SESSION` in every terminal, so `REX_SESSION` alone never marks a round. Covered by `tests/test_rex_team.sh`, which runs the documented one-liner verbatim with a hostile block id, and `tests/test_rex_team_env.py`.

### Changed

- **`rules/agent-team-operation.md` Two Modes names the Rex entry point** and states that `REX_SESSION` alone never marks a team round.
- **A Rex team round needs a bound Claude Code lead, and keeps its native Stop backstop.** `supervision-bind` under `TEAMLEAD_BACKEND=rex` binds a Claude Code lead to the session id Claude Code exports (`CLAUDE_CODE_SESSION_ID`), once the adapter confirms Claude Code is the lead pane's agent, with source `claude-code:env`. `apply` under `rex` refuses any dispatch unless its caller is that bound lead, for this pane and this session; Herdr's unbound legacy dispatch does not exist in Rex. The team contract requires supervision before dispatch, and `supervision-watch` needs a bound owner. Codex and other leads export no session id and are not supported on Rex: their bind and dispatch are refused with the way to start a Claude Code lead. The Stop hook blocks a `claude-code:env` binding outside `TEAMLEAD_BACKEND=rex`. Tested both ways through the CLI (`tests/test_supervision_cli.py`), through `hooks/herdr-supervision-stop.sh` (`tests/test_supervision.py`), and through `HerdrClient` over the adapter (`tests/test_rex_herdr_core.py`).
- **Supervision binding records converge on version 2 (`skills/herdr-teamlead/state-schema.md`).** Every binding now names what proved it: `herdr:<kind>` (Herdr's native proof), `operator:record` (`--record`), `claude-code:env` (Rex), or `herdr:unrecorded` (migrated). The owner writes only version 2. Its `load` and `bind` upgrade a version-1 record and rewrite the owner document and discovery record, idempotently. The Stop hook never migrates. It reads a version-1 record as no usable prior state and lets the stop proceed with a stderr warning to run `supervision-status`, because blocking on a record it may not migrate would trap the lead in a stop loop (`rules/stateful-artifacts.md` Cross-Pipeline Schema Bumps). The review rejected the earlier dual-accept, which never migrated version 1.
- **`label-workspaces.sh` reads `TEAMLEAD_BACKEND` like `teamlead.herdr.default_backend`.** It refuses any value other than `herdr` or `rex`, and under `rex` it refuses before any rename: one Rex session holds the team and a block label is the agent's name, so labelling would overwrite worker names. Tested in `tests/test_label_workspaces.sh`.

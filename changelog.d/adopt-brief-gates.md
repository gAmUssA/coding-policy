### Added

- **ADR 0005** (`docs/adr/0005-report-gate-lines.md`) records the report gate-line contract.
- **Worker reports carry a machine-readable `## Gates` section, and the lead checks it in code.** The developer, tester (Modes B and C) and reviewer brief templates require one line per gate, `- <name> exit=<code> cmd=<exact command>`, with the real exit code of the final run or `unknown`. A new read-only `teamlead check-gates --report <path> [--require NAME]` command (`skills/herdr-teamlead/teamlead/gates.py`) exits non-zero when the section is missing, duplicated, empty, malformed, names a gate twice, lacks a required gate, or carries any non-zero or `unknown` exit. Fenced code never counts (CommonMark fence matching, backtick or tilde), the section runs to the next level-1 or level-2 heading so gates under `###` children are validated, every Markdown list entry in it must be canonical, and a blank command is refused. `record-report` now refuses an `approved` review whose gates are not green. `references/round-flow.md` Reading a Report says when the lead runs it. Adapted from drover's `bin/fleet-done` evidence gate and `skills/roles/coder.md` (`126def9`, `9757a55`): the recurring defect class was a report claiming more than ran, and prose acceptance could not catch it. No state record shape changed; historical imported reviews (`record-historical-review`) predate the contract and stay unchecked. Proven by `tests/test_gates.py`, `tests/test_recovery.py` `test_approved_review_requires_green_gate_lines`, and the `record-report` CLI accept and reject cases in `tests/test_recovery_cli.py`; the reject cases fail with the guard reverted and the accept case fails when approvals are wrongly refused.

### Changed

- **Reviewer brief: negatives need proof, and unexplained deletions are reported and classified by effect.** A reviewer never asserts that something is absent or unused without pasting the command and its output. It reports every deleted file that no commit message or PR body explains and classifies it under `rules/review-severity.md`: blocking when behavior or a contract changes, advisory when only an explanation is missing. Negative claims are a common hallucination shape in model reviews (drover `skills/fleet-peers/SKILL.md` Reviewers; LESSONS "Name every deletion", `a7e17b9`). drover makes every unexplained deletion fail review; that ignores our behavioral severity test, so we classify instead.
- **`## BLOCKED` names a person and an action; a finding in your own branch is never a blocker** (`templates/COMMON.md` Reporting). This cuts BLOCKED reports the lead has to turn around (drover LESSONS, `d421e6c`).
- **Workers never print the environment or process argv** (`env`, `printenv`, `ps` with a command column), one line in `templates/COMMON.md`. Child processes inherit credentials and pane text is captured. The lead's own argv verification runs inside the owner script and is unaffected (drover `skills/fleet-peers/SKILL.md` Never).
- **`templates/COMMON.md` Policy and the developer brief point to the rules instead of restating them.** The restated error-handling bullet had already drifted from `rules/error-handling.md` (it lacked `|| :`). Pointers were cheaper and more honest than a drift test, which would have forced verbatim copies of rule text into every dispatch. `COMMON.md` shrank from 1158 to 1135 words despite the two new lines (drover `bin/fleet-rules-sync`, `9757a55`; LESSONS "One authority per clause", `ee82a13`).

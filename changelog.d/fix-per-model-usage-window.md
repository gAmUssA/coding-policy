### Fixed

- **`herdr-teamlead` scopes a Claude seat's headroom to the model it runs**. Claude's `/usage` now prints a per-model weekly window (`Current week (Fable)`) beside `Current week (all models)` and `Current session`, and `headroom_pct` took the minimum across all of them. Once the Fable-only window was spent, every Claude seat read 0% headroom, an Opus 5.5 judge included, and `plan` halted every judge round with "There is no substitute judge" (#69). `measure` now counts a per-model window only for a seat whose `model_label` names that model; the account-wide windows bind every seat, and a seat with no `model_label` keeps every window. `plan` re-reads each record's stored `windows` under the model the seat runs this round, the pinned `judge.model` for the judge and the tier row's `model` otherwise. This covers both ranking and judge affordability across the pool, so a Fable sibling on the same account no longer re-imposes the Fable window on an Opus judge. The decision is recorded in `docs/adr/0013-model-scoped-usage-headroom.md`. Snapshots move to `schema_version` 4 and every agent record gains `headroom_model`, the `model_label` its headroom was scoped to. The owner's `3 → 4` migration stamps it empty and keeps the version-3 all-window minimum, which is the version-4 reading for an unknown model, so a migrated record never claims more headroom than it measured. Proven by tests in `test_parsers.py`, `test_measure.py`, `test_planner.py` and `test_state.py` built on the real 2026-10-23 snapshot, each shown failing before the fix.

### Fixed

- **`parse_claude_usage` reads both layouts of Claude Code's `/usage` dialog**. The same build stacks the header, `N% used`, and `Resets` at a pane width of 62 columns or more, and below 62 prints `Current session · Resets 5pm (America/New_York)`, with `(America/New_York)` able to wrap onto the next line and `N% used` after the bar. The matcher required the header alone on its line and only read a `Resets` line after the percentage, so `measure` raised "No usage windows found". A narrow pane that ends the header at ` · `, or on the word `Resets`, keeps the reset text from the next line, including a wrapped `(UTC)` zone and a time phrase split across lines. A second `N% used` row under a label that already has one raises `ParseError` instead of dropping that window, and the message names the label above and the wrapped line when one was seen: a header wrapped after `Resets` had left `measure` reporting headroom 95 where the account week was 61. Credit sections (`Claude Code and Cowork credit`, `Credit`, `Usage credits`) render another `N% used` row and are not rate-limit windows, so they no longer fail the read. A header with no percentage, or a percentage above the first header, means the pane cut the dialog: the read raises and names a taller pane, instead of returning the windows that remain. Proven by the captured pane in `skills/herdr-teamlead/tests/test_parsers.py`, `skills/herdr-teamlead/tests/test_parsers_claude_layouts.py`, and `skills/herdr-teamlead/tests/test_parsers_claude_adversarial.py`.

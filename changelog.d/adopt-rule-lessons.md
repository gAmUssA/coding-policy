### Changed

- **Tightened six always-on rules with lessons from `andrebrov/drover` and upstream `jbaruch/coding-policy`** (+1,443 bytes in `rules/`, about 350 tokens). Each bullet folds into the section that already covers the neighbouring case, so no existing bullet is restated.
  - `rules/error-handling.md`: a check that cannot reach a verdict reports unknown or fails, never pass, and a missing or stale result reads as failure (drover `12407ca` "Failure is unknown, not clean"). Our session-start hooks are non-fatal by design, which is where "could not check" most easily reads as "fine". Shell: `x=$(cmd)` under `set -e` exits silently, so a status that matters is captured with `if` or `|| rc=$?` (drover `12407ca`). The existing `grep` 1-vs-2 bullet stays the tool-specific case.
  - `rules/testing-standards.md` Coverage: a guard's accept case runs through its documented entry point (the hook as the agent invokes it, the CLI, the workflow), and a config change is tested in every environment class it reaches (drover `7127d9f`, `a7e17b9`: a gate whose must-fire tests called the SQL directly could never be satisfied through the real migration runner). Extends the existing two-direction guard bullets.
  - `rules/testing-standards.md` Assertions: a boundary mock proves shape, never validity; text crossing a boundary runs once against the real counterparty or a recorded contract (drover `ee82a13`, `12407ca`: a mock accepted SQL naming a missing column, and a provider swap shipped on fake-client tests alone). A status write ships with a test where its dependency fails and the record reads failed or unknown (drover `d421e6c`). This is the counterweight to the existing licence to mock at the process boundary.
  - `rules/testing-standards.md` Determinism: a non-deterministic evaluation (Tessl evals, model or tier trials) runs at least 3 times and reports the spread, never the best run (drover `d421e6c`). "Flaky tests are bugs" still governs deterministic tests.
  - `rules/testing-standards.md` Fixtures: tests never read machine-local paths (drover `efabdac`: one such test refused every push for two hours).
  - `rules/agent-worktree-isolation.md`: restore or revert by path, never with `checkout .`, `reset --hard`, `clean -fd` or a pathless `stash` (drover `fleet-peers` Never, `e6b6eac`). `rules/verify-before-done.md` asks for a fix shown failing with the change reverted, which invites exactly these commands against the operator's uncommitted work.
  - `rules/verify-before-done.md` Report Faithfully: exit 126 or 127 reports "did not run" only when the wrapper confirms the command never launched; a command that launched and then exited 126 or 127 is a failure, since a script can propagate either status from a missing helper (drover `ee82a13`, narrowed after review).
  - `rules/cross-boundary-changes.md` Map Before Editing: a new governed path maps every other writer of the same object and routes or removes each in the same change (drover `7127d9f`). The consumer map did not catch a competing second writer.
  - `rules/dependency-management.md`: a lock file is one this repo's build, test or CI reads; per-machine installer state such as `skills-lock.json` is not one and may be gitignored (upstream `1be06a0`, where the reviewer blocked a consumer PR twice for gitignoring it).
  - Post-edit audit found no drift: test fixtures that name `/Users/...` are string literals, every test touching `HOME`/`XDG_*` points it at a temp dir, no script or skill uses a tree-wide git restore, `scripts/run-tests.sh` already treats a missing interpreter as a setup error rather than a failing suite, and the hooks' command substitutions already capture `|| rc=$?` and report "sync not verified" when a fetch fails.

### Added

- **Configurable judgment pins: `top_models` in config.json.** An optional top-level `{kind: [model id, ...]}` block extends the built-in `TOP_MODELS` per kind, never replacing it. Validation is strict (known kinds, non-empty arrays of distinct model ids); an id already built in is accepted so a later built-in addition never breaks a config. The effective pins reach tier parsing, `select_tier`'s high-risk top-model switch, and the `judge` check. The block needs config schema 4; schemas 1 to 3 stay readable unchanged, and one carrying `top_models` is refused with the instruction to set `schema_version` 4 (the operator owns that bump; the Codex policy reviewer asked for an explicit version instead of a silent shape change). Decision recorded in `docs/adr/0009-configurable-top-model-pins.md`. Fixes #47, where a 0.7.10 config broke on upgrade because the frozen allowlist lagged the CLIs.

### Changed

- **`rules/stateful-artifacts.md`: operator-authored configuration exception.** Migration Policy gains a narrow exception, with seven atomic preconditions, for a file no skill writes: the owner reads every documented version and upgrades in memory only, refuses a version-gated field in an older file with the version to set, and its schema doc lists the gates. The Codex policy reviewer flagged that the config's 1-3 to 4 bump had no owner migration; the coordinator chose not to let teamlead rewrite the operator's config, so the rule names the alternative instead. herdr-teamlead's `config.json` takes it: `state-schema.md` cites it with the gate table (`tiers` 2, `capabilities` 3, `top_models` 4; `launch_args` ungated, correcting the doc that said schema 2 added it), and the `tiers` and `capabilities` refusals now name the file, the agent index and `set "schema_version" to N`.

- **Built-in pins track the current CLIs.** Codex adds `gpt-6-astra` and `gpt-6.1-sol`; Claude adds `opus-5-5` and `claude-fable-5-1` (`claude-opus-5-5` was already pinned). Superseded ids stay.
- **Codex accepts `max` and `ultra` effort.** codex-cli 0.160.0 lists `low, medium, high, xhigh, max, ultra` as `supported_reasoning_levels` for `gpt-6.1-sol`, `gpt-6-astra` and `gpt-5.6-sol` (`~/.codex/models_cache.json`); `codex exec --help` documents no effort enum. Risk escalation no longer lowers a `max` or `ultra` row to `xhigh`.
- **The judge block meets the judgment floor.** When the judge's agent is configured, its model must be a pin of that agent's kind (`top_models` included) at high effort or above; `preflight` now checks the judge before any worker contact. A judge on an unpinned model, previously accepted silently, is refused with the `top_models` fix named. A configured judge agent whose kind has no pins or effort floor is refused instead of passing silently; a judge naming an undeclared agent is still left to the planner. Test fixtures that pinned the judge to retired ids (`claude-opus-4-6`, `grok-4`) move to current pins.

### Fixed

- **`start-judge`'s config is part of its contract.** `start-judge` compares the plan against the current config, but neither `start-judge-worker.sh` nor SKILL.md Step 14 named `--config`, so a round planned on a non-default config was compared against the default one (Codex policy review on PR #54). The launcher header and usage now carry `[--config FILE]` (forwarded to `teamlead.sh`, which already accepted it) and refuse a `--config` without a path; SKILL.md's preflight, measure, plan, start-judge and apply blocks, `references/round-setup.md`, and the retrospective and recovery command notes pass the round's same `--config`.
- **A non-string agent `kind` is a config error, not a crash.** A list or object `kind` reached the top-model lookup and raised `TypeError` with a traceback, bypassing the structured error (Copilot on PR #54). `validate_config_schema` now refuses it before any pin lookup, for every reader.
- **Every config.json reader checks the schema first.** `parse_judge` and `parse_role_costs` skipped `parse_config`'s readable-version check, so a schema 5 config's `judge` and `role_costs` were consumed (Codex policy review on PR #54). Schema and field-gate validation now live in one function, `validate_config_schema`, which all three readers (and their `load_*` loaders) run before reading a field; a newer, older-unreadable or missing version and an under-versioned gated field are refused. The `top_models` guard is also exercised through the real `teamlead.sh plan` entry point (`tests/test_top_models_cli.py`).
- **Retained fixes rank effort on the shared order.** `assign.py` kept a private rank table ending at `max`, so a verified `ultra` session was refused an `ultra` retained fix and a `high` or `xhigh` session silently continued below a requested `ultra` (found by Copilot on PR #54). The check is now `retained_developer_tier`, ranking on `tiers.EFFORT_ORDER`; no other private effort table exists.
- **A refused judgment row says what to change.** The error names the agent, the round, the refused model and effort, the accepted models and efforts for that kind, and `top_models.<kind>` in config.json, with the same facts in the error details.
- **`start-judge` checks the plan against the current config.** It used to trust the plan's tier and the caller's `--kind`, validating the pair only as a non-judgment build row. It now loads the current config before any Herdr contact and refuses a plan whose judge agent, model, effort or kind differs from the configured judge block and its agent, or whose pair misses the effective judgment floor.
- **An explicit `"top_models": null` is refused.** It read as an omitted block; it is now refused as a non-object like any other malformed value, through the `teamlead.sh plan` entry point as well.
